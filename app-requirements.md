Product Requirements Document (PRD)Project OverviewThe goal is to create a mobile application that allows a grocery store owner to quickly digitize their entire inventory and export it as an Excel/CSV file for integration into their billing software. Manually scanning and typing details for 1,000–2,000 items takes days and is highly prone to human error (e.g., typos). This app leverages AI and mobile cameras to fully automate data extraction.📋 Data Schema RequirementsThe app must generate a structured dataset for each product containing the following fields:product_item_id: Barcode or unique identifier from the product packaging.product_name*: Name of the item.product_category*: High-level category (e.g., Eatables, Washing, Cleaning, Masala, Milk Products).product_sub_category: Fine-grained category mapping.standard_size: Net weight or volume (e.g., 500g, 1kg, 100ml).mrp*: Maximum Retail Price.selling_price: Defaults to MRP; editable by the shopkeeper during the final verification stage.mfd: Manufacturing Date (if applicable).expiry_date: Expiration Date (if applicable).quantity*: Number of items in stock (entered manually).image_urls: Array of strings pointing to public image paths stored on a CDN.purchase_amount: Cost price paid to the distributor (entered manually).rack_no: Physical storage location coordinates in the store (e.g., Row/Column like 1A, 2B).Fields marked with an asterisk () are mandatory.*🛠️ User Workflow & High-Level Functionality1. Staged AI Data Capture (Multi-Step Wizard)Camera Initialization: The user taps a floating + (Add Item) button to open a custom, staged camera interface.Staged Photography: To avoid confusing the AI with overcrowded packaging data, photos are captured in distinct sequential stages (e.g., Stage 1: Front Panel, Stage 2: Rear Panel / Ingredients & Dates).Cropping/Highlighting: The UI allows the user to visually highlight or crop specific portions of the package to focus the AI's attention on dates or nutritional blocks.Progress Indicator: A thin green progress bar stays anchored at the top of the screen, dynamically showing the completion percentage as the user completes each wizard stage.2. Live AI Interleaving & Temporary CachingEach photo is initially saved to a secure local temporary app folder.When the user taps the Check button on an intermediate stage, the app uploads the image to a cloud storage bucket and instantly dispatches the URL to a multimodal AI model (e.g., Google Gemini API).The AI processes the image with a strict structural prompt and streams back a JSON payload containing the extracted fields.The screen updates instantly, allowing the user to review or edit the AI's predictions before tapping Next to move to the subsequent stage.3. Final Verification & Database IngestionThe Review Dashboard: The final page of the wizard aggregates all AI-extracted information into a single comprehensive, editable form.Manual Overrides: On this page, the user manually fills out transactional metrics that the packaging cannot provide: physical stock Quantity, Purchase Amount, and any necessary Selling Price adjustments.Database Sync: Tapping the final submit button pushes the fully validated record into a persistent document or relational storage repository.4. Animations & Micro-InteractionsUpon successful database ingestion, a success screen loads for a brief duration, rendering a clean SVG checkmark animation.Simultaneously, a real-time system notification updates a global badge count on an Alert Counter Button located at the top-right corner of the primary dashboard screen.The form automatically resets, priming the camera interface immediately for the next product scanning loop.5. Reconciliation & Export ControlTapping the alert/history badge routes the user to a Reconciliation Dashboard.This view groups and sums items to display macro metrics: total item counts, cumulative invoice costs, projected sales values, and estimated net profit margins.Once validated, the user can tap an export action to compile a localized Excel (.xlsx) or CSV file, firing a native sharing sheet to send it straight to the software vendor via WhatsApp.💻 Technical StackFrontend: React Native engineered via the Expo framework (utilizing Expo Router for file-based navigation).Backend & File Storage: Firebase (Firestore and Cloud Storage) or Supabase (PostgreSQL and Storage Buckets).AI Inference Layer: Google Gemini API (utilizing Flash tiers for real-time speed and low operational overhead).📝 Key Assumptions & Architectural GoalsScaling Threshold: Optimized to smoothly catalog a baseline target of 1,000 to 2,000 distinct stock-keeping units (SKUs).Metadata Tracking: Every document automatically records system metadata—including user_id, created_at, and updated_at timestamps—for auditing and historical logging.Zero Bottlenecks: Heavy networking, image manipulation, and base64 parsing loops must execute on background threads to ensure smooth 60fps UI transitions.Security & Longevity: Enforce strict security access patterns (e.g., Row-Level Security rules or Firebase Security Rules) to keep data secure. Code must be cleanly separated into modular components for long-term maintainability.
